Arquitectura actual

El runtime de IA se organiza por roles. El Backend API funciona como capa de control, el RAG local recupera evidencia desde documentos y el runtime de modelos genera respuestas. Cada peticion enviada desde esta consola a /chat debe quedar registrada como run del backend. El frontend no lee SQLite, PDFs ni chunks directamente.

Diagnostico de fallos

Connection refused

El servicio no esta escuchando en ese puerto.

Timeout

Firewall, IP incorrecta, ruta de red o servicio no accesible.

CORS error

El origen del frontend no esta permitido por el Backend API.

NO_EVIDENCE_FOR_ANSWER

RAG no encontro evidencia usable; el fallback puede responder con conocimiento del modelo.

Run no aparece

Revisa que el backend tenga ruta de trazas escribible y que /api/traces/chat responda.

sqlite no such table documents

Fallo antiguo ya protegido; si reaparece indica DB o esquema invalido.
